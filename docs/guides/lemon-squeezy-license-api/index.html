The Lemon Squeezy License API, and how to move off it

If your app checks licenses with Lemon Squeezy, it makes up to three calls. This page lists them, the fields your code likely depends on, and what has to stay the same when you move them somewhere else before Lemon Squeezy stops on March 31, 2027.

The three calls

All three are POST requests to https://api.lemonsqueezy.com/v1/licenses/… with a form-encoded body and Accept: application/json. They take the license key itself, not your store API key, which is why they can be called from inside a shipped app.

CallYou sendYour app usually reads
/v1/licenses/activatelicense_key, instance_nameactivated, error, instance.id (store it), license_key.status, activation_limit, activation_usage
/v1/licenses/validatelicense_key, optional instance_idvalid, error, license_key.status, license_key.expires_at
/v1/licenses/deactivatelicense_key, instance_iddeactivated, error

Many apps also check the meta object (store_id, product_id, variant_id) so a key bought for one product can't unlock another. License status is one of inactive, active, expired or disabled. Check Lemon Squeezy's License API docs for the full response.

What has to survive the move

  1. The keys. Customers have them in emails and password managers. Reissuing keys means support mail from every customer.
  2. The instance ids. Your app stored one from each activate call and sends it on every validate. If the new server doesn't know them, each customer has to activate again and may hit the activation limit.
  3. The product checks. If your code compares meta.product_id or variant_id, the new server must return values your shipped code accepts, or you have to change that code too.
  4. Old versions. Copies that still call api.lemonsqueezy.com stop validating when Lemon Squeezy goes. Decide now what those copies should do on a failed check.

The free export tool downloads every key and every activation (including instance ids) into one CSV, using a read-only API key.

Make the next move cheap

Whatever you move to, ship one update now that does two things:

  • Reads the license server's base URL from one setting, so the next change is a config value, not a code change.
  • Has a grace period: if the license server can't be reached, keep the last good result for some days instead of locking a paying user out.
// Sketch: one base URL, cached result, 14-day grace when offline
const LICENSE_BASE = config.licenseBase; // e.g. "https://api.lemonsqueezy.com"

async function checkLicense(key, instanceId) {
  try {
    const res = await fetch(`${LICENSE_BASE}/v1/licenses/validate`, {
      method: "POST",
      headers: { Accept: "application/json",
                 "Content-Type": "application/x-www-form-urlencoded" },
      body: new URLSearchParams({ license_key: key, instance_id: instanceId }),
    });
    const data = await res.json();
    cache.save({ valid: data.valid, checkedAt: Date.now() });
    return data.valid;
  } catch {
    const last = cache.load();
    const graceMs = 14 * 24 * 3600 * 1000;
    return !!last && last.valid && Date.now() - last.checkedAt < graceMs;
  }
}

Ship this before you pick a new provider. Every user who updates now is one fewer copy that breaks in March.
